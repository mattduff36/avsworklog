# Private performance regression checks

Run `npm run test:performance:structural` for the fast deterministic gate. It uses the existing terminal test runner and fixed synthetic fixtures to check lightweight, complete HGV/plant lists, inventory hint reuse, lazy retired data, targeted refreshes, maintenance enrichment and PDF page planning. Missing test files or dependencies fail before starting. No server, database setup, account provisioning or upload runs.

For browser checks, start an approved local application build yourself on port 4100, then run `npm run test:performance:browser`. Set `PERF_BASE_URL` to another localhost port if needed. The browser command rejects remote hosts, uses the existing admin in the gitignored `testsuite/.state/test-users.json`, and permits only reads and normal login. It will fail if login needs a password change; it never changes passwords or provisions accounts. The local app may still use the shared database, so business writes and telemetry are blocked in the browser.

The browser gate measures the initial HGV projection/window/response bytes, initial inventory requests with count-only retired reads, maintenance response bytes and retained canvases after deep scrolling through an 80-page mixed/rotated synthetic PDF. It also proves that an intentionally oversized 80-canvas observation fails the allocation guard. The six-canvas bound applies to the tested 1200 by 850 viewport and visible-page/neighbour policy, not every conceivable viewport.

Only sanitized counts, byte sizes and timing observations are written to the gitignored `testsuite/.state/performance/latest.json`. No response bodies, credentials, cookies, signed URLs, page HTML, screenshots, traces or HAR are saved by this command. Nothing uploads to Lighthouse temporary storage. Existing `test:lighthouse` remains a separate login-only command with its original configuration; do not use it for private authenticated artifacts.

Timings describe one authenticated local-server pass with no cache reset. They are observations, not p95 estimates or release budgets. Calibrate any future latency budget through repeated comparable builds, datasets, roles and cold/warm conditions. Structural checks are the reliable gate today. No CI or scheduled job is enabled. The release owner maintains the fixture contracts and rechecks this small gate when the corresponding data loaders, payloads or PDF renderer change.
